# Objective
Validate SvcForge against a real service application and the real OpenRC manager using the isolated `/root/Dex-srvforge` laboratory.

# Decisions made
- Dex-srvforge consumes the published GitHub pseudo-version for SvcForge; no local `replace` is used.
- The integration installs the real service name `dex` and binary `/usr/bin/dex` to exercise self-update/self-remove behavior.
- `/etc/dex` is persistent application data: it is snapshotted for transactions but intentionally preserved by remove.
- Dex configuration creation runs through `LifecycleHooks.BeforeMutation`, so it is inside rollback scope.
- Health validation uses the application's final bind address and `/healthz`.
- The legacy installer was removed from the test path; `scripts/install.sh` only delegates to the candidate binary's `--install`.

# Architecture validated
Dex-srvforge embeds a SemVer version with `-X main.version=<version>`, defines one SvcForge `App`, and maps `--install`, `--repair`, `--remove`, `--status` and `--version` to the lifecycle Runner. OpenRC definitions are generated by SvcForge at runtime.

# Libraries used
SvcForge remains standard-library-only. Dex-srvforge consumed `github.com/YahirHub/svcforge` from GitHub.

# Real host test results
- Legacy Dex was backed up, stopped, removed from OpenRC and its installed binary/config/log files were removed for a clean test.
- Fresh install 0.1.0: passed; config created, OpenRC detected, enabled+started, health 200, installed SHA matched source.
- Same-version install: passed; PID/config/manifest remained unchanged and repair was suggested.
- Repair of a modified OpenRC definition: passed.
- Repair of a modified stopped binary: status detected SHA mismatch; repair restored the binary and started the service.
- Upgrade 0.1.0 -> 0.2.0: passed; config remained byte-identical.
- Forced 0.3.0 health failure: passed; SvcForge rolled back to 0.2.0, restored service state and returned health to OK.
- `/usr/bin/dex --remove`: passed while executing from the installed binary; service/runlevel/binary/manifest were removed and persistent config was preserved.
- Reinstall after remove: passed and reused persistent config.
- Backup retention: capped at five snapshots.
- Final installed runtime: Dex-srvforge 0.2.0, OpenRC started, `/healthz` OK.

# Problems found
The old Dex-srvforge copy still used Dex's legacy `--install` behavior, which only created config and did not exercise SvcForge. This explained the user's initial install/remove results.

# Solutions implemented
Dex-srvforge now routes the full lifecycle through SvcForge, and the library gained a rollback-covered `BeforeMutation` hook plus fresh-install snapshots for declared persistent targets.
